# Tiny Experiment Content Style

Write like a quiet technical lab notebook.

## Public Voice

- Use first person when it clarifies ownership.
- Prefer short paragraphs and concrete nouns.
- Name uncertainty without dramatizing it.
- Explain the practical lesson, not every step of the session.
- Keep the note useful for a future reader who did not see the chat.

## Entry Shape

Each public log entry should answer:

- What happened?
- What changed?
- What did I learn?
- What is the next small test?

## Avoid

- Raw transcript excerpts.
- Prompt dumps.
- Private account, client, credential, or infrastructure details.
- Claims that sound final when the experiment is still exploratory.
- Marketing language about building in public.
